# Bsi

BSI، سامانه فارسی بازرسی گزارش‌های سرفصل بانکی با تم آبی. بررسی فایل روی دستگاه بازرس انجام می‌شود و به API یا سرویس هوش مصنوعی احتیاج ندارد.

## اجرا

Node.js 22 یا جدیدتر:

```powershell
npm ci
npm run build
node scripts/setup.mjs
npm start
```

رمز دلخواه را در مرحله setup وارد کنید. تنظیمات در `.env` محلی ذخیره می‌شود. آدرس اجرا `http://localhost:3000` است. رمز در JavaScript مرورگر یا مخزن قرار نمی‌گیرد. فایل نمونه بانکی، گزارش و فایل‌های محیطی از Git و انتشار حذف شده‌اند.

## استفاده

با رمز وارد شوید و یک فایل XLSX تا ۱۰ مگابایت انتخاب کنید. قالب گزارش شامل ردیف، سرفصل، معین، م، عنوان حساب، کد سپهری و هفت ستون تعداد/گردش/مانده است. جای ستون‌ها می‌تواند تغییر کند، ولی عنوان‌ها باید مطابق قالب باشند. شیت نامعتبر به‌صورت «بررسی نشده» نمایش داده می‌شود.

صفحه یافته‌ها جستجو، فیلتر، صفحه‌بندی و شواهد ردیف اصلی دارد. خروجی CSV، یافته‌های فیلترشده را می‌دهد. دکمه چاپ/PDF تمام یافته‌ها را چاپ می‌کند. اعداد صحیح با BigInt پردازش می‌شوند. مقادیر ناامن عددی، داده خالی، خطای اکسل و فرمول بدون مقدار ذخیره‌شده به‌عنوان مشکل کیفیت داده گزارش می‌شوند. فرمول‌های اکسل محاسبه مجدد نمی‌شوند.

## قواعد

- کنترل مانده = گردش بستانکار − گردش بدهکار.
- تطبیق هفت ستون جمع سرفصل با معین‌ها و جمع کل بدون شمارش دوباره جمع‌ها.
- مانده خلاف ماهیت با معافیت حساب‌های دوماهیته.
- ناسازگاری تعداد و مبلغ روز، گردش منفی یا روز بیشتر از تجمعی.
- شناسه‌های تکراری، ناقص و ساختار نامعتبر.
- پیگیری مانده حساب‌های مغایرت و موقت با حد بررسی قابل تنظیم.
- فهرست مطالبات غیرجاری براساس عنوان معین یا سرفصل مادر.

حد پیش‌فرض یک میلیارد واحد فایل، انتخاب تحلیلی است و حد قانونی نیست. واحد همه حساب‌ها به‌طور قطعی از این فایل قابل استنباط نیست؛ اقلام ارزی و انتظامی باید جداگانه تفسیر شوند. یافته، نشانه نیاز به رسیدگی است. گزارش تجمیعی برای کشف تمام تخلف‌ها، تراکنش مشکوک، اشخاص مرتبط، وضعیت وثیقه یا قدمت مانده کافی نیست. تأیید تعریف شمارنده‌ها و ریز اسناد بانک ضروری است.

## گزارش اولیه محلی

فایل اولیه بدون تغییر خوانده شده است. داده و نتیجه واقعی در پوشه خصوصی `private` می‌مانند. فایل `outputs/BSI-report.html`، نسخه مستقل گزارش با رمزگذاری AES-256-GCM و کلید مشتق‌شده با PBKDF2-SHA256 (۶۰۰ هزار تکرار) است. فایل HTML را در مرورگر جدید باز کنید و با رمز تعیین‌شده وارد شوید. وابستگی‌ها در آن قرار دارند و نیازی به اینترنت ندارد. رمز کوتاه در برابر حدس آفلاین قوی نیست؛ این خروجی برای تحویل محلی است. برای میزبانی از نسخه سرور با رمز قوی استفاده کنید.

خواندن دوباره منبع محلی (Python با openpyxl لازم است):

```powershell
python scripts/extract.py 'C:/path/to/report.xlsx'
```

این اسکریپت فقط داده را در `private/workbook.json` ذخیره می‌کند. پس از ورود، دکمه نمونه محلی آن را باز می‌کند. پوشه private روی Vercel منتشر نمی‌شود؛ آنجا فایل را از دستگاه انتخاب کنید.

## انتشار Vercel

مخزن را Import کنید. Build command برابر `npm run build` است. `vercel.json` مسیر API را به تابع Node هدایت می‌کند. دو متغیر زیر را برای محیط Production (و برای تست Preview) از تنظیمات محلی خود در Vercel تنظیم کنید:

- `BSI_PASSWORD_HASH`: هش scrypt و salt تولیدشده توسط setup، بدون رمز خام.
- `BSI_SESSION_SECRET`: کلید تصادفی تولیدشده توسط setup.

متغیرها را در Git قرار ندهید. در صورت تنظیم نبودن، ورود با خطای مشخص غیرفعال می‌ماند. نشست امضاشده چهار ساعت اعتبار دارد و کوکی HttpOnly و SameSite=Strict دارد؛ روی HTTPS کوکی Secure است. محدودکننده ورود فعلی در حافظه همان نمونه سرور است؛ برای استفاده سازمانی چندنمونه‌ای، محدودکننده مشترک و مدیریت کاربران/ابطال نشست اضافه شود. خروج، کوکی مرورگر را پاک می‌کند؛ ابطال نشست‌های کپی‌شده به زیرساخت نشست مرکزی نیاز دارد.

## آزمون

```powershell
npm test
```

تست‌ها، دقت عددی، عدم دوباره‌شماری جمع، کشف تغییر داده، مقادیر خالی، قالب نامعتبر، ارث‌بری سرفصل مطالبات، تغییر ترتیب ستون‌ها و شناسه تکراری را پوشش می‌دهند.

ExcelJS 4.4.0 برای خواندن XLSX استفاده می‌شود. `npm audit` یک advisory متوسط در uuid قدیمی مورد استفاده ExcelJS گزارش می‌کند (GHSA-w5hq-g745-h8pq). مسیر v3/v5/v6 با buffer که موضوع advisory است در منطق BSI فراخوانی نمی‌شود؛ بسته مرورگر توزیع‌شده upstream نیز به‌صورت مستقیم استفاده می‌شود. این وابستگی پیش از استفاده سازمانی باید بازبینی/جایگزین شود.
